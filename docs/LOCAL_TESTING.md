# Local End-to-End Testing Guide (DPBA with Ollama)

This guide walks you through setting up and running the Databricks Pipeline Builder Assistant (DPBA) completely locally, using Ollama for Component 1's AI extraction and the deterministic components 2 and 3 for the code generation.

## Prerequisites

1. **Python 3.10+** (The project is now compatible with 3.9+)
2. **Ollama** installed on your local machine ([Download Ollama](https://ollama.com/download))

## 1. Setup the Project Environment

First, ensure your Python dependencies are installed. In the root of the repository, run:

```bash
python3 -m pip install -e '.[dev]'
```

This installs the `dpba` package, its dependencies (including `pydantic`), and the development tools (`pytest`).

## 2. Start the Ollama Server & Pull the Model

Open a new terminal window and start the Ollama server:

```bash
ollama serve
```

In your main terminal, pull the required model. The project defaults to `qwen3.6`, but if you are using a specific tag (e.g., `qwen:7b`, `qwen2.5:7b`), you should pull that exact model:

```bash
# Example pulling qwen2.5 (adjust the model name to match your company's standard)
ollama pull qwen2.5:7b
```

## 3. Configure the Environment

The project reads configuration from environment variables. You can set them in your terminal before running the tool:

```bash
export OLLAMA_BASE_URL="http://localhost:11434"
export OLLAMA_MODEL="qwen2.5:7b"  # <--- Change this to the exact model you pulled
export DPBA_LLM_MAX_RETRIES="2"
export LOG_LEVEL="INFO"
```

*(Note: You can also place these variables in a `.env` file or export them from `.env.example`)*

## 4. Run the Pipeline End-to-End

We have provided a sample business requirements document at `tests/fixtures/sample_specs/sample_requirements.md`. You can feed this directly into the CLI.

Run the full end-to-end extraction and generation:

```bash
python -m dpba run tests/fixtures/sample_specs/sample_requirements.md --output ./artifacts/local_output
```

**What happens during this run?**
1. **Component 1 (AI)** reads the markdown file and sends it to Ollama with a strict JSON schema prompt.
2. Ollama returns a structured mapping.
3. **Pydantic Validation** kicks in. If the model hallucinated or returned an invalid structure, the tool automatically sends a "Repair Prompt" back to Ollama with the specific validation errors to fix.
4. **Component 2 (Data Gen)** uses the validated mapping to deterministically generate CSV test fixtures and edge cases.
5. **Component 3 (Pipeline Builder)** generates the Databricks Asset Bundle (`databricks.yml`, job definitions, and PySpark notebooks).

## 5. Inspect the Output

Navigate to the `./artifacts/local_output` directory to see the results:

```bash
cd ./artifacts/local_output
ls -la
```

You will see:
- `test_data/` â€” Contains the `synthetic_input.csv` and `expected_output.csv` generated by Component 2.
- `pipeline/` â€” Contains the `databricks.yml`, `resources/pipeline_job.yml`, and the `notebooks/` directory generated by Component 3.
- `pipeline_spec.json` â€” The intermediate structured JSON that Component 1 extracted from your text document.

## 6. Run the Test Suite

To verify the deterministic components and schema parsers, run the pytest suite:

```bash
python -m pytest
```

If you want to run the tests that actually call your live Ollama server (ensure Ollama is running):

```bash
export DPBA_LLM_INTEGRATION_TESTS=1
python -m pytest -m ollama
```

## The Recommended JSON Template

If you prefer to bypass Component 1 (the AI) and write the structured mapping yourself, or if you need a template to understand the exact structure Component 1 is trying to produce, you can find a comprehensive template at:

**[`tests/fixtures/sample_specs/recommended_template.json`](tests/fixtures/sample_specs/recommended_template.json)**

This template includes inline `_comment` fields explaining every supported transformation type (`cast`, `concat`, `conditional`, `date_format`, `lookup`, `split`, etc.) and every data expectation action (`drop_row`, `quarantine`, `fail_pipeline`). You can copy this file, remove the `_comment` keys, modify it for your specific pipeline, and pass it directly to the builder:

```bash
python -m dpba run my_custom_mapping.json --output ./artifacts/my_pipeline
```
